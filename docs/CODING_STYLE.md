# 源码与接口约定

2026/9/30 By JiTianYu391

维护的源码、汇编、链接脚本和构建脚本采用 Uinxed-Kernel 的块式文件头：项目内路径、职责、修改日期与作者、项目版权。Python 保持 shebang 为首行；配置/构建文件使用 `#`，Rust/汇编/链接脚本使用 `/* ... */`。第三方与自动生成文件保留原作者和声明。

```rust
/*
 *
 *       src/subsystem/file.rs
 *       Concrete responsibility of this file
 *
 *       2026/9/30 By JiTianYu391
 *       Copyright (C) 2026 ViudiraTech.
 *
 */
```

许可声明来自本项目自己的许可决定，不照搬参考项目的许可证。Rust 模块职责用 `//!`，公开 API 的参数、失败方式、所有权和并发条件用 `///`。需要调用者维持不变量的接口应声明为 `unsafe` 并写 `# Safety`；每个 unsafe 块说明已成立的不变量，而非重复说“这是安全的”。

注释解释布局、硬件规则、锁顺序和非显然的决策，避免逐句翻译代码。寄存器位和协议常量优先命名；解析器检查长度、字段取值与溢出，未知值返回错误或显式未知。能力判断区分硬件支持与 OS 已启用状态。架构差异放后端，共享代码只依赖语义接口。

提交前运行 `cargo fmt --all -- --check`、三目标检查及相应 `make test`；涉及 CPU 状态的更改还要验证 debug/release ELF 的 FP/SIMD 指令分布。硬件、保存区布局或中断代码的测试要经过真实指令/中断路径，不能仅模拟调用 Rust 分发函数。
