# 分页、CPU 能力与扩展状态审查记录

2026/9/30 By JiTianYu391

本轮在 `codex/sv39-cpu-state` 上完成实现、实现后的第二轮审查及回归。审查重点是分页几何、寄存器所有权、固件字段边界、错误回滚、真实异常/中断路径与编译器指令生成；本记录不表示全仓库没有缺陷。

## 实现结果

- RISC-V 默认 Sv39；可选 Sv48。VMM 使用架构分页几何计算规范地址、根槽大小和页表级数，根表切换保留实际 SATP 模式。
- 公共 `cpuid` 接口提供不可变、无锁读取的 BSP 能力快照；x86 CPUID、AArch64 ID 寄存器、RISC-V SBI/设备树各自实现后端。未知信息保持未知，数值厂商/修订 ID 不截断。
- 公共 `fpu` 接口提供对齐的任务状态、主动切换、克隆/重置、经过校验的状态导入、AP 初始化和显式 `with_kernel` 辅助入口。普通内核使用整数/soft-float ABI，并保持本 CPU 的 FP 门关闭。
- x86 管理 x87/MMX/SSE、标准格式 XSAVE 的 AVX，以及硬件具备时的 AVX-512 状态；AArch64 管理全部 Q 寄存器及 FPCR/FPSR；RISC-V 管理 F/D 及 FCSR。
- 源码、汇编、链接脚本与构建工具补充块式文件头，署名 JiTianYu391；补充模块职责、寄存器布局、并发/所有权及关键 unsafe 注释。第三方和自动生成文件保留原声明。

## 已修复的问题

| 问题与影响 | 修复 |
| --- | --- |
| 原 VMM 固定四级和 48 位根槽，无法正确使用 Sv39 | 三级/四级几何、规范地址计算、启动请求/响应检查、SATP 模式保留 |
| 页表缺页时逐层发布，分配失败可能留下半成品；可能把大页当成下级表 | 私有子树全部成功后一次发布，OOM 归还页框，验证描述符类型与物理地址 |
| RISC-V 非叶页表发布只刷新一个虚拟页，允许留下旧的遍历缓存 | 非叶发布走独立刷新接口，SFENCE.VMA 使用 rs1=rs2=x0；叶页继续使用按地址刷新 |
| 设备范围溢出、非法物理地址进入映射器 | checked 算术和映射前边界检查 |
| x86 新 GDT 与 IDT 中沿用的启动 CS 不一致，真实 timer IRQ 触发异常 | 所有 IDT 门使用最终代码段 selector，保留正确 IST |
| AArch64 从 EL1t 切换到 EL1h 时未设置活动 SP_EL1，真实 IRQ 返回路径损坏 | 在切换 SPSel 时保留当前栈指针 |
| 扩展状态没有统一所有权/保存区和能力门槛 | 不透明 State、硬件初始化模板、主动保存/恢复、校验导入、借用结束恢复原状态与门 |
| 内核 codegen 可能使用 RISC-V F/D ABI；仅编译成功无法证明 IRQ 不破坏寄存器 | RISC-V 改为 imac/整数 ABI；最终 ELF 指令检查；真实寄存器和 timer IRQ 自测 |
| RISC-V 将厂商 ID 截断到 family，并可能从 ISA 命名扩展误判 F/D | 保留完整 SBI 数值 ID；区分单字母、版本号、Z/S/X 命名扩展 |
| x86 缺失拓扑叶时将硬件 ID 缩成 8 位；AP 策略未拒绝更窄地址宽度 | 使用启动器完整 APIC ID 作为回退；能力兼容检查同时验证地址宽度 |
| RISC-V 状态导入允许保留 frm 值 | 拒绝 frm=5/6/7，失败不修改原状态 |
| PMM 重复可用区重复计数；元数据页可被 free；扫描 hint 可能错失连续区 | 去重、排除位图页、长度溢出检查、完整回绕扫描 |
| PCI 64 位 BAR 在递增索引后存到了错误槽位 | 记录低槽索引后再解析/推进 |
| MCFG 起始总线非 0 时 ECAM 地址减错 bus offset | 将 MCFG 的 bus-0 base 正规化为窗口首总线地址，检查溢出并增加非零 start_bus 回归 |
| FDT PCI bus-range 截断、reg/ranges cell 数导致算术风险 | 验证长度、窄化范围、窗口大小及 cell 上界 |
| SBI v0.2 IPI 把 mask 的指针当成 mask 值传入 | 标准 SBI 传值；legacy 入口按其指针契约传入并返回错误 |
| PLIC 通过 `2*hart+1` 或零号 hart 猜上下文，非零 BSP 可能操作错误上下文 | 从 interrupts-extended 与 CPU intc phandle 解析；检查 source/MMIO 边界；sscratch 对照已发布指针 |
| GICv3 redistributor 越过固件范围、找不到本 CPU 时退回其他 CPU、SGI 字段错误、PPI 未配置 | 有界亲和匹配、正确 VLPIS 步长、正确 SGI 编码、PPI 配置及超时错误 |
| 生成 DTB 的 CPU 数和运行 QEMU 不一致，非零 RISC-V BSP 可能启动失败 | DTB 与运行使用相同 machine/CPU 数/内存/CPU 配置 |
| 测试仅看到 BOOT_OK，可能漏掉子系统自测 | 必须同时观察 CPU/FPU 与原有自测标记；保留失败诊断并回收 QEMU 进程 |

MCFG 地址规则依据 [Linux PCI/ACPI 文档](https://www.kernel.org/doc/html/latest/PCI/acpi-info.html)：MCFG base 始终对应 bus 0。CPU/分页设计依据与接口契约见 [CPU_STATE.md](CPU_STATE.md)，文件头参考与写法见 [CODING_STYLE.md](CODING_STYLE.md)。

## 验证

静态检查：`make check`（rustfmt 与三个 target 的 all-features 检查）、三目标 `cargo clippy --all-features -- -A dead-code -D clippy::all`、Python 脚本语法检查、`git diff --check`。未启用的 AP/驱动/未来接口仍有 dead-code 警告，未以全局代码属性隐藏。

下列启动均通过 CPU/FPU 状态隔离、保存/恢复、嵌套借用、非法导入，以及内存/TTY/IRQ/FDT 自测与 BOOT_OK；受支持的中断控制器完成真实 timer IRQ。debug/release 构建的最终 ELF 通过普通代码 FP/SIMD 指令检查。

| 平台/路径 | debug | release |
| --- | --- | --- |
| x86 QEMU qemu64，FXSAVE 512 字节 | 通过 | 通过 |
| x86 QEMU max，XSAVE 832 字节，XCR0=7，AVX | 通过 | 通过 |
| x86 QEMU max,avx=off，XSAVE 576 字节，XCR0=3 | 通过 | 通过 |
| x86 KVM host，Intel Core i5-9400F，XSAVE/AVX、x2APIC | 未单独运行 | 通过 |
| AArch64 QEMU virt，GICv2，FP/AdvSIMD | 通过 | 未单独运行 |
| AArch64 QEMU virt,gic-version=3，GICv3，FP/AdvSIMD | 通过 | 通过 |
| RISC-V QEMU virt，Sv39，D 状态 | 通过 | 通过 |
| RISC-V rv64,sv48=false,sv57=false，Sv39-only CPU | 通过 | 未单独运行 |

基本复现：

```sh
make check
make test ARCH=x86_64 CONFIG_BOOT_SELF_TEST=y
make test ARCH=aarch64 CONFIG_BOOT_SELF_TEST=y
make test ARCH=aarch64 MACHINE=virt,gic-version=3 CONFIG_BOOT_SELF_TEST=y
make test ARCH=riscv64 CONFIG_BOOT_SELF_TEST=y
make test ARCH=riscv64 CONFIG_RISCV_SV48=y CONFIG_BOOT_SELF_TEST=y
# 对上面的命令增加 PROFILE=release 可复现对应 release 路径。
```

兼容路径在已有 x86 ISO 上运行：

```sh
python3 tools/qemu_test.py x86_64 \
  build/x86_64/release/SpaceKernel-x86_64.iso \
  /usr/share/OVMF/OVMF_CODE_4M.fd 4 512 --cpu max \
  --require 'CPU/FPU self-test passed' \
  --require 'hardware timer IRQ self-test passed'
# --cpu max,avx=off 检查仅 SSE 的 XSAVE；--cpu host --accel kvm 检查本机硬件路径。
```

RISC-V Sv39-only 复现需先构建 Sv39 ISO，然后对 `tools/qemu_test.py` 使用 `--cpu rv64,sv48=false,sv57=false`。固件路径需按本地安装调整；KVM 测试仍是虚拟机环境，不是裸机测试。

## 尚未完成的集成与验证

仓库当前仅运行 BSP，尚无调度器和用户态返回路径。因此本次提供的扩展状态接口还没有实际线程迁移、用户异常/signal ABI、AP 上线和跨核压力验证。把未来接入入口写好不等于完成这些系统能力；目前不能把本项目称作完整工业级内核或已完成工业级全平台验证。

VMM 没有解除映射、用户权限接口和跨核 TLB shootdown；设备映射保持单调，范围部分失败可能保留已经成功映射的页面。PLIC 需要设备树描述 hart 上下文，ACPI-only 上下文发现未实现。

AVX-512 状态后端已实现但本次硬件/模拟配置没有覆盖；RISC-V F-only、缺少 FP 的 CPU 和更多 AMD 型号未实际启动验证。AArch64/RISC-V 缓存与拓扑信息不从缺失的固件数据猜测。SVE/SME、RVV、AMX 等可变或附加状态保持未开放；它们不属于已验证的 State ABI。

下一阶段需要围绕真实调度器/用户入口接入主动状态切换与门控制，完成 AP 能力交集、异构保存区策略、SMP/TLB shootdown、架构用户异常处理，以及裸机和长期负载回归。这些工作应在相应子系统存在后验证，不能以当前启动自测代替。
